## 1. 始める前の準備

自分で作った作業用の AWS CLI プロファイルの名前と、管理者から受け取ったリージョン・開催設定の場所を入力します。右上の設定と同期します。空欄や形式不正は保存されず、コマンドには未設定表示が残ります。設定欄は AWS ログインやファイルの編集を実行しません。

### 1.1 管理者に依頼するもの

次のものを AWS アカウントの管理者に依頼し、そろったら印を付けてください。

- [ ] 構築担当の作業用の権限（IAM Identity Center のユーザー、または IAM ユーザーに、管理者が付与します。構築・撤去に必要な権限の一覧は [アクセス制御の仕様](<<= guide_link('staff/environment/specs/access-control.md') =>>) の「必要な IAM 権限」にあります。`AdministratorAccess` があれば足ります）
- [ ] 対象のアカウント・リージョンでの CDK のブートストラップ（[AWS アカウントの状態を確かめる](<<= guide_link('staff/preparation/environment-start.md#13-aws') =>>) で確かめます）
- [ ] GPU インスタンスの vCPU クォータの引き上げ（[AWS アカウントの状態を確かめる](<<= guide_link('staff/preparation/environment-start.md#13-aws') =>>) で足りないと分かった場合）
- [ ] AMI が AWS Marketplace の製品の場合は、その製品の購読（利用規約への同意を伴うため、管理者が行います）
- [ ] [（任意）ソフトウェアを導入済みの AMI を用意する](<<= guide_link('staff/preparation/ami-find.md#24-ami') =>>) でソフトウェアを導入済みの AMI を新しく作る場合は、AMI を作る権限（一覧は [アクセス制御の仕様](<<= guide_link('staff/environment/specs/access-control.md') =>>) の「管理者の作業」）と、一時的なインスタンスに付けるインスタンスプロファイル（AWS 管理ポリシー `AmazonSSMManagedInstanceCore` を付けたロールのもの）の名前

AWS CLI のプロファイルは、管理者に依頼するものではありません。上の権限を付与されたユーザーを使って、構築担当が自分の作業環境に作ります。上の入力欄の「AWS プロファイル」には、そのときに付けたプロファイルの名前を入れます。

作り方は、AWS の公式ページを参照してください。IAM Identity Center のユーザーの場合は[AWS CLI を使用した IAM アイデンティティセンター認証の設定](https://docs.aws.amazon.com/ja_jp/cli/latest/userguide/cli-configure-sso.html)、IAM ユーザーの場合は[AWS CLI の設定ファイルおよび認証情報ファイルの設定](https://docs.aws.amazon.com/ja_jp/cli/latest/userguide/cli-configure-files.html)です。この資料での準備の流れは、[AWS アカウントの状態を確かめる](<<= guide_link('staff/preparation/environment-start.md#13-aws') =>>)にもあります。

### 1.2 道具を入れる

次の道具を入れます。
リポジトリの dev container（`.devcontainer/`）を使う場合は、すべて入っているので、下の版の確認から行ってください。

- Python 3.11 以上と [uv](https://docs.astral.sh/uv/)
- AWS CLI v2
- Node.js と AWS CDK の CLI

AWS CDK の CLI を入れます。

```bash
npm install -g aws-cdk
```

まとめて版を確認します。道具名の後にバージョンが表示されれば成功です。失敗した道具名が表示されたら、その道具を入れてからやり直します。

```bash
(
  set -e
  for tool in uv aws cdk; do
    printf '\n%s: ' "$tool"
    "$tool" --version || {
      printf '%s の版を確認できませんでした。\n' "$tool" >&2
      exit 1
    }
  done
)
```

リポジトリ直下で、運用ツールと構築用のツールを入れます。

```bash
uv sync
```

`gclue-ai-handson-cdk` の使い方が表示されれば成功です。

```bash
uv run gclue-ai-handson-cdk --help
```

### 1.3 AWS アカウントの状態を確かめる

ここで使うのは、アカウントを変更しない確認のコマンドだけです。
Claude Code を使う場合は、Skill `handson-preflight-check` で同じ確認をまとめて行えます。

以下の AWS CLI コマンドは、入力したプロファイルとリージョンを引数へ直接入れます。プロファイルは実行する dev container 内で定義済みである必要があります。

認証方式に合わせて名前付きプロファイルを準備します。
{: #sso-login}

{% include 'common/aws-profile-auth.md' %}

- [ ] **アカウント ID が正しいこと**

  表示された1列目の12桁のアカウント ID と、2列目の利用者・ロールの ARN が管理者の指定と一致することを確かめます。アカウント ID だけを下の欄へ転記します。例: `123456789012`。IAM ユーザーで直接実行する場合は利用者、ロールを使う設定ではそのロールの ARN になります。

  ```bash
  aws --profile {{PROFILE_SH}} --region {{REGION}} \
    sts get-caller-identity --query '[Account,Arn]' --output text
  ```


<div data-aws-values-panel data-aws-inline data-aws-fields="ACCOUNT_ID"></div>

- [ ] **CDK のブートストラップが済んでいること**

  数字（ブートストラップの版）が表示されれば済んでいます。
  `ParameterNotFound` と表示された場合は、管理者に次の実行を依頼してください。

  ```bash
  cdk --profile {{PROFILE_SH}} bootstrap \
    aws://{{ACCOUNT_ID}}/{{REGION}}
  ```

  ```bash
  aws --profile {{PROFILE_SH}} --region {{REGION}} \
    ssm get-parameter --name /cdk-bootstrap/hnb659fds/version \
    --query Parameter.Value --output text
  ```

- [ ] **GPU インスタンスの vCPU クォータが足りること**

  クォータ（Running On-Demand G and VT instances）の値を表示します。

  ```bash
  aws --profile {{PROFILE_SH}} --region {{REGION}} \
    service-quotas get-service-quota --service-code ec2 \
    --quota-code L-DB2E81BA --query 'Quota.Value' --output text
  ```

  インスタンスタイプ 1 台あたりの vCPU 数を表示します（`g6e.2xlarge` は 8）。

  ```bash
  aws --profile {{PROFILE_SH}} --region {{REGION}} \
    ec2 describe-instance-types --instance-types {{INSTANCE_TYPE}} \
    --query 'InstanceTypes[0].VCpuInfo.DefaultVCpus' --output text
  ```

  すでに動いているインスタンスを表示します。
  G や VT で始まるインスタンスタイプがあれば、その vCPU 数も数に入れます。

  ```bash
  aws --profile {{PROFILE_SH}} --region {{REGION}} \
    ec2 describe-instances \
    --filters Name=instance-state-name,Values=pending,running \
    --query 'Reservations[].Instances[].[InstanceId,InstanceType]' \
    --output text
  ```

  「受講者数 × 1 台あたりの vCPU 数 ＋ すでに動いている G・VT 系の vCPU 数」がクォータ以下であれば足ります。
  足りない場合は、管理者にクォータの引き上げ申請を依頼してください。

- [ ] **VPC をもう 1 つ作れること**

  講習会ごとに専用の VPC を 1 つ作ります。
  1 つ目のコマンドで VPC 数の上限（既定は 5）、2 つ目で今ある VPC の数を表示します。
  今ある数が上限より小さければ足ります。

  ```bash
  aws --profile {{PROFILE_SH}} --region {{REGION}} \
    service-quotas get-service-quota --service-code vpc \
    --quota-code L-F678F1CE --query 'Quota.Value' --output text
  ```

  ```bash
  aws --profile {{PROFILE_SH}} --region {{REGION}} \
    ec2 describe-vpcs --query 'length(Vpcs)' --output text
  ```

AMI と Availability Zone の確認は、[開催の設定ファイルを用意する](<<= guide_link('staff/preparation/event-settings.md#2') =>>)で設定ファイルを書きながら行います。
