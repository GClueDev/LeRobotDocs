## 2. 教材の版を作って公開する

今回公開する教材フォルダの実パスと、未使用の版名を入力します。例: `/home/teacher/materials` と `workshop01-v1`。版名は作業前に決め、作成済み版を上書きしません。

<div data-aws-values-panel data-aws-inline data-aws-fields="MATERIALS_DIR RELEASE"></div>

教材の版とは、受講者の EC2 の `/opt/handson/` に置く講義資料・ツールの一式に、`v1` や `2026-10-23.1` のような名前（版の識別子）を付けたものです。
版の識別子は英数字で始まる英数字・`.`・`_`・`-` の 64 文字以内で付けます。
公開した版は変更せず、訂正するときは新しい名前の版を作ります（[教材の版と一斉配布の仕様](<<= guide_link('staff/instructor/contracts.md') =>>)）。

### 2.1 版を作る

```bash
uv run gclue-ai-handson release build --version {{RELEASE}} \
  --materials {{MATERIALS_DIR_SH}}
```

- `{{RELEASE}}`: 新しい版の識別子（例: `v1`）
- `{{MATERIALS_DIR}}`: 受講者の EC2 の `/opt/handson/` に置く内容のディレクトリ。中にシンボリックリンクがあると作れません。

受講者の手元の機器（Jetson・PC）で、教材の取得後に準備（教材ごとの Python 環境の用意など）が必要な場合は、その準備をするスクリプトを `--edge-setup-hook <スクリプト>` で加えます。
このスクリプトは受講者の機器で、受講者が教材を取得するたびに実行されます（書き方の約束は [教材の版と一斉配布の仕様](<<= guide_link('staff/instructor/contracts.md') =>>)）。

<div data-aws-values-panel data-aws-inline data-aws-fields="EDGE_SETUP_HOOK"></div>

```bash
uv run gclue-ai-handson release build --version {{RELEASE}} \
  --materials {{MATERIALS_DIR_SH}} \
  --edge-setup-hook {{EDGE_SETUP_HOOK_SH}}
```

確認: 次の 3 行が表示されれば成功です。
最後の行の SHA-256（64 桁の英数字。版の中身を表す指紋）は、一斉配布のときに使うので控えておきます。

```text
版のディレクトリ: build/handson-releases/{{RELEASE}}
ファイル数: <数>
manifest の SHA-256: <64 桁の英数字>
```

公開する前の版を作り直すときは `--force` を付けます。版を変更すると、以前の manifest ハッシュはフォームから消えます。同じ版を作り直した場合も、新しい build のハッシュを必ず入力し直してください。JSON で版だけを入れ替えた場合も古いハッシュは消えます。版とハッシュを一緒にインポートした場合は、その組を採用します。

`release build` が最後に表示した `manifest の SHA-256:` の後の64桁だけを下の欄へ転記します。形式例は64個の `a` ですが、実際の出力を使います。任意 hook を使う場合は実ファイルのパスを入力してから、hook 付きの build を行います。

<div data-aws-values-panel data-aws-inline data-aws-fields="MANIFEST_SHA"></div>

### 2.2 版を公開する

```bash
uv run gclue-ai-handson release publish --env-dir {{CONFIG_DIR_SH}} \
  --version {{RELEASE}}
```

確認: `版 {{RELEASE}} の manifest の SHA-256: ...` と `現行版を {{RELEASE}} にします: ...` が表示されれば成功です。

- 公開した版は、そのまま「現行版」になります。現行版は、受講者が手元の機器で版を指定せずに教材を取得したときに使われる版です。
- 公開だけしておき、あとで現行版に切り替える場合は `--no-latest` を付けます。
- 受講者の EC2 には、公開しただけでは配られません。手順 4 で一斉配布します。

### 2.3 現行版を切り替える・前の版に戻す

公開済みの版を現行版にします。
`--no-latest` で公開しておいた版への切り替えや、前の版への差し戻しに使います。

```bash
uv run gclue-ai-handson release promote --env-dir {{CONFIG_DIR_SH}} \
  --version {{RELEASE}}
```

確認: `現行版を {{RELEASE}} にします: ...` と表示されれば成功です。
受講者の手元の機器には、受講者が次を実行したときに反映されます。

```bash
gclue-ai-handson-attendee env update
```

受講者の EC2 は切り替わらないため、EC2 も戻す場合は手順 4.2 で戻したい版を指定して配り直します。
