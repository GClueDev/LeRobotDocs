## 3. 受講者に認証情報を渡す

認証情報には有効期限があり、`--duration-seconds <秒>` で講義の長さに合わせて決めます（例: 8 時間なら `28800`）。

- 指定できるのは 900 秒以上、設定の `max_session_duration_seconds`（最大 43200 秒 = 12 時間）までです。上限を超える値は、注意を表示して上限で発行します。
- 一度渡した認証情報の期限は延ばせません。期限が切れたら、もう一度発行して渡し直します。
- 講師の認証方式にかかわらず、この手順のコマンドで発行してください。本環境は払出し専用 IAM ユーザーからの発行だけを許可します。ロールの一時認証情報で別のロールを引き受ける場合には、AWS のロール連鎖の制約で最長 1 時間になります。講師自身の IAM ユーザーの恒久的なキーで直接引き受ける場合はこの制約の対象ではありませんが、本環境の信頼ポリシーでは許可されません（[アクセス制御の仕様](<<= guide_link('staff/instructor/contracts.md') =>>)）。

`--attendee {{ATTENDEE_ID}}` を付けるとその受講者だけに、付けないと設定ファイルの全受講者に発行します（`--attendee` は複数指定できます）。

### 3.1 受講者の EC2 へ直接書き込む

手元にファイルを残さずに、受講者ごとの EC2 へ書き込みます。
EC2 上の学習ジョブから受講者自身の保存場所へ成果をアップロードするのに必要です。
受講者の EC2 が起動していること、手元に AWS CLI v2 と Session Manager プラグイン（SSM 経由のシェル接続・ポート転送用）があることが必要です。

```bash
uv run gclue-ai-handson credentials send --env-dir {{CONFIG_DIR_SH}} \
  --ec2 --duration-seconds 28800
```

確認: 受講者ごとに `受講者 {{ATTENDEE_ID}} の一時認証情報（有効期限 ...）を <インスタンス ID>（ubuntu） の ... に書き込みました。` と、続けて `source /tmp/gclue-ai-handson-{{EVENT_ID}}-{{ATTENDEE_ID}}.env` の行が表示されれば成功です。

EC2 のツール導入時は、このファイルを読み込んで使います。[EC2 に受講者ツールを用意する](<<= guide_link('staff/preparation/rollout.md#ec2-attendee-tools') =>>) でツールを導入してから受講者の作業を始めます。導入済みの場合は、[EC2 に受講者ツールを用意する](<<= guide_link('staff/preparation/rollout.md#ec2-attendee-tools') =>>) の認証情報更新も実施してください。元のファイルを読み込むだけでは、ツール導入先の認証情報は更新されません。

```bash
source /tmp/gclue-ai-handson-{{EVENT_ID}}-{{ATTENDEE_ID}}.env
```

### 3.2 SSH で入れる機器（Jetson など）へ直接書き込む {#ssh-host-check}

講師の PC から、パスワードの入力なしに入れる機器へ 1 名分ずつ書き込みます。最初に **講師の PC のターミナル** で接続を確認します。`<ホスト>` は相手の SSH 接続先へ手動で置き換えます。

SSH 接続先欄へ、接続確認する Host 名を入力します。例: `ubuntu@jetson04.local`。

<div data-aws-values-panel data-aws-inline data-aws-fields="SSH_HOST ATTENDEE_ID"></div>

```bash
ssh {{SSH_HOST_SH}}
```

対象機器のプロンプトが表示されたら、その機器上で次を実行して講師の PC に戻ります。

```bash
exit
```

講師の PC の運用リポジトリ直下で、認証情報を書き込みます。

```bash
uv run gclue-ai-handson credentials send --env-dir {{CONFIG_DIR_SH}} \
  --ssh-host {{SSH_HOST_SH}} --attendee {{ATTENDEE_ID}} \
  --duration-seconds 28800
```

- `<ホスト>`: ssh の宛先（例: `ubuntu@jetson04.local`、または `~/.ssh/config` の Host 名）
- `{{ATTENDEE_ID}}`: その機器を使う受講者の ID（例: `user04`）

確認: `... を <ホスト> の /tmp/gclue-ai-handson-{{EVENT_ID}}-{{ATTENDEE_ID}}.credentials, /tmp/gclue-ai-handson-{{EVENT_ID}}-{{ATTENDEE_ID}}.env に書き込みました。` と表示されれば成功です。

受講者に伝えること: 初めて導入する場合は、本人の機器で[期限付き導入 URL からスクリプトを取得する手順](<<= guide_link('setup.md#2') =>>)に従って `bootstrap.sh` を取得します。そのファイルがあるフォルダで、次を実行します。

```bash
bash bootstrap.sh \
  --env-file /tmp/gclue-ai-handson-{{EVENT_ID}}-{{ATTENDEE_ID}}.env
```

導入済みで認証情報を入れ替える場合は次を実行します。

```bash
gclue-ai-handson-attendee env credentials \
  --env-file /tmp/gclue-ai-handson-{{EVENT_ID}}-{{ATTENDEE_ID}}.env
source ~/gclue-ai-handson/{{EVENT_ID}}/activate
gclue-ai-handson-attendee env info
```

`/tmp` は機器の再起動で消えることがあります。
受講者が導入する（または入れ替える）前に再起動した場合は、もう一度書き込みます。

### 3.3 ファイルに書き出して渡す

受講者ごとのファイルを手元に書き出し、安全な方法で受講者に渡します。最初に、保存先が Git 管理対象外であることを確認します。次のパスが表示された場合だけ発行へ進みます。

```bash
git check-ignore {{CONFIG_DIR_SH}}/credentials/probe.env
```

```bash
uv run gclue-ai-handson credentials issue \
  --env-dir {{CONFIG_DIR_SH}} --duration-seconds 28800 \
  --output-dir {{CONFIG_DIR_SH}}/credentials
```

確認: `開催 {{EVENT_ID}} の一時認証情報を <人数> 名分発行しました（有効時間 <秒> 秒）。` と、受講者ごとのファイルの場所（既定の `sh` 形式では `{{CONFIG_DIR}}/credentials/{{ATTENDEE_ID}}.env`）が表示されれば成功です。

- 既定の `sh` 形式では、一時認証情報を含む `.env` 1ファイルを本人へ渡します。`--format aws-profile` を指定した場合だけ、`.env` と同名の `.credentials` の2ファイルが必要です。2つを同じフォルダにそろえて渡します。
- 下記の事前確認で管理対象外と確認してから発行してください。表示されなければ発行を止め、構築担当に保存先の設定を依頼します。
- ファイルには秘密の値が入っています。本人以外に渡らないようにし、渡し終えたら手元のファイルは削除します。
- 書き出し先は `--output-dir <ディレクトリ>` で変えられます。
- Windows の PowerShell で読み込む形式が必要な場合は `--format powershell` を付けます。

### 3.4 設定JSONを一緒に生成する

一時認証情報をファイルに書き出した直後に、本人ごとの各種値の設定JSONを作成できます。[設定JSON生成スクリプト](<<= guide_link('assets/downloads/export_attendee_guide_settings.py') =>>)を保存してください。このスクリプトはPython 3の標準ライブラリだけで動作します。

実行場所: **講師のPC**。下の欄へ保存した生成スクリプトの絶対パスを入力します。例: `/home/teacher/tools/export_attendee_guide_settings.py`。[ファイルに書き出して渡す](<<= guide_link('staff/instructor/operations.md#33') =>>)で作成した認証情報の出力先に対して実行します。


<div data-aws-values-panel data-aws-inline data-aws-fields="GUIDE_EXPORTER"></div>

```bash
python3 {{GUIDE_EXPORTER_SH}} \
  --credentials-dir {{CONFIG_DIR_SH}}/credentials
```

出力先に `受講者ID.guide-settings.json` が作成されます。既に生成済みなら更新します。`.env` の確定した開催ID・受講者ID・S3バケット・リージョンだけを取得し、認証情報本体・認証ファイルのパス・講師側の設定は含めません。`.env` は実行せず、必要な項目を読み取ります。全員分の値を検証してから書き出します。異なる開催のファイルや不正な値が混ざる場合は生成を止めます。

データセットのディレクトリと識別名も確定している場合だけ、次のように追加します。未確定の項目は指定せず、上の基本コマンドを使います。確定済みなら下の欄へ入力して追加コマンドを使います。

<div data-aws-values-panel data-aws-inline data-aws-fields="DATASET_DIR DATASET_REPO_ID"></div>


```bash
python3 {{GUIDE_EXPORTER_SH}} \
  --credentials-dir {{CONFIG_DIR_SH}}/credentials \
  --dataset-dir {{DATASET_DIR_SH}} \
  --dataset-repo-id {{DATASET_REPO_ID_SH}}
```

一時認証情報の発行に続けて生成する場合は、次の順で実行します。発行が失敗した場合は設定JSONの生成へ進みません。

```bash
uv run gclue-ai-handson credentials issue \
  --env-dir {{CONFIG_DIR_SH}} --duration-seconds 28800 \
  --output-dir {{CONFIG_DIR_SH}}/credentials &&
python3 {{GUIDE_EXPORTER_SH}} \
  --credentials-dir {{CONFIG_DIR_SH}}/credentials
```

本人へ `.env` と対応する `.guide-settings.json` を渡します。`aws-profile` 形式の場合は `.credentials` も一緒に渡します。受講者は「各種値の設定」の「インポート」でJSONを読み込みます。認証情報の期限更新で設定JSONを再生成しても、一時認証情報はJSONに入りません。

EC2やSSHへ直接渡す[受講者の EC2 へ直接書き込む](<<= guide_link('staff/instructor/operations.md#31-ec2') =>>)・[SSH で入れる機器（Jetson など）へ直接書き込む](<<= guide_link('staff/instructor/operations.md#ssh-host-check') =>>)の場合、設定JSONは講師のフォームの「受講者向けをエクスポート」で作成し、本人に別途渡せます。生成スクリプト自体はAWSへの発行や受講者への送信を行いません。

受講者には [導入・認証更新のコマンド](<<= guide_link('staff/instructor/support.md') =>>) を案内します。認証ファイルのパスを本人が手動で置き換えます。
