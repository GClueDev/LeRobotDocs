## 6. 開催中に変更する

!!! warning "開催中の変更は未検証です"
    この節は仕様と CLI の照合に基づく手順で、実 AWS での通し実行は未実施です。[未検証と未完了の記録](<<= guide_link('staff/environment/verification.md#unverified') =>>)を確認してください。

開催設定ファイル `{{CONFIG_DIR}}/gclue-ai-handson-config.yml` の必要な項目を書き換えて、もう一度 [作られるものを確かめる](<<= guide_link('staff/preparation/validate.md#32') =>>)（diff）と [構築する](<<= guide_link('staff/preparation/deploy.md#4') =>>)（deploy）を行います。

> **注意: インスタンスが作り直される変更があります**
>
> 次の表の「作り直し」の変更をすると、受講者の EC2 は削除されて新しく作られ、中のファイルはすべて消えます。
> 必ず先に [作り直しの前の準備](<<= guide_link('staff/environment/procedures/environment.md#61-作り直しの前の準備') =>>) の準備をしてください。
>
> | 変更する項目（用途） | 起きること |
> | --- | --- |
> | `ami_id`（起動元 AMI）、`root_device_name`（起動ディスク名）、`root_volume_size_gb`（容量）、`instance.availability_zone`（配置先の区画） | 全受講者の EC2 の作り直し |
> | `vpc_cidr`（ネットワークの範囲）、`availability_zones`（区画の一覧）、`max_azs`（区画数） | VPC と全受講者の EC2 の作り直し |
> | 受講者一覧 `attendees` から受講者 ID を消す | その受講者の EC2 の削除 |
> | `instance_type`（CPU・GPU などの機器構成） | 全受講者の EC2 の停止と起動（ファイルは残るが、動いている処理は止まる） |
> | 受講者一覧 `attendees` に受講者 ID を加える | その受講者の EC2 の追加（他の受講者には影響なし） |
> | `max_session_duration_seconds` | これから払い出す認証情報の有効期間の上限が変わる（EC2 には影響なし） |
> | `access_key_serial`（アクセスキーの更新番号） | 一時 AWS 認証情報発行用アクセスキーの作り直し（[払出し用の鍵を作り直す](<<= guide_link('staff/environment/procedures/environment.md#64') =>>)） |
> | `deployment_id`、`account`、`region` | 別の環境として新しく作られる。開催中は変えない |
>
> 構築用のコードを更新した場合も、[作られるものを確かめる](<<= guide_link('staff/preparation/validate.md#32') =>>) の diff で `replace`（作り直し）と表示されるものがないか確かめてください。

### 6.1 作り直しの前の準備 {#61-作り直しの前の準備}

1. 受講者に、変更の時刻と、残したい成果を S3 へ保存してほしいことを伝えます。
2. [作られるものを確かめる](<<= guide_link('staff/preparation/validate.md#32') =>>) の diff を実行し、作り直されるもの（`requires replacement` と表示されるもの）を確かめます。
3. 作り直される・削除される EC2 の「終了保護」（誤って削除されないようにする設定）を外します。外さないと、古い EC2 を削除できずに deploy が失敗するか、古い EC2 が残ります。

   ```bash
   aws --profile {{PROFILE_SH}} --region {{REGION}} \
     ec2 modify-instance-attribute --instance-id {{INSTANCE_ID}} \
     --no-disable-api-termination
   ```

4. [構築する](<<= guide_link('staff/preparation/deploy.md#4') =>>)の deploy を実行します。新しく作られた EC2 には、終了保護が自動で付きます。
5. 作り直した EC2 は空の状態です。講師に、教材の一斉配布（初回の環境構築）のやり直しを依頼してください（[講師の手順](<<= guide_link('staff/environment/handoff.md') =>>)）。

### 6.2 受講者を増やす

1. 開催設定ファイルの受講者一覧 `attendees` に受講者 ID を加えます。
2. [AWS アカウントの状態を確かめる](<<= guide_link('staff/preparation/environment-start.md#13-aws') =>>) の vCPU クォータが、増やした後の台数でも足りることを確かめます。
3. [作られるものを確かめる](<<= guide_link('staff/preparation/validate.md#32') =>>) の diff で、加えた受講者の EC2 だけが `[+]` と表示されることを確かめます。
4. [構築する](<<= guide_link('staff/preparation/deploy.md#4') =>>)の deploy を実行します。
5. 講師に、加えた受講者への教材の配布と認証情報の払出しを依頼します。

受講者 ID を一覧に加えて deploy するまで、その受講者の認証情報は作れません。

### 6.3 インスタンスタイプを変える

1. 受講者に、EC2 が再起動することと、その時刻を伝えます。
2. 増やす場合は、[AWS アカウントの状態を確かめる](<<= guide_link('staff/preparation/environment-start.md#13-aws') =>>) の vCPU クォータが足りることを確かめます。
3. [作られるものを確かめる](<<= guide_link('staff/preparation/validate.md#32') =>>) の diff と [構築する](<<= guide_link('staff/preparation/deploy.md#4') =>>)の deploy を実行します。

### 6.4 払出し用の鍵を作り直す

一時 AWS 認証情報の発行に使う、払出し専用 IAM ユーザーのアクセスキーを更新します。漏れた疑いがあるとき、または定期的に行います。

1. 開催設定ファイル `{{CONFIG_DIR}}/gclue-ai-handson-config.yml` の `aws.handson_cdk.issuer.access_key_serial`（アクセスキーの更新番号）の値を 1 増やします。
2. [作られるものを確かめる](<<= guide_link('staff/preparation/validate.md#32') =>>) の diff と [構築する](<<= guide_link('staff/preparation/deploy.md#4') =>>)の deploy を実行します。
3. [払出し用の鍵ができたことを確かめる](<<= guide_link('staff/preparation/verify.md#51') =>>) のコマンドで、パラメータがあることを確かめます。

講師の側で行う作業はありません（講師のコマンドは、実行のたびに新しい鍵を読みます）。
古い鍵で作った受講者の認証情報は、有効期限まで使えます。
すぐに使えなくする必要がある場合は、講師に認証情報の失効を依頼してください（[講師の手順](<<= guide_link('staff/environment/handoff.md') =>>)）。
