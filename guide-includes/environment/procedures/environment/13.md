## うまくいかないとき

| 症状 | 対処 |
| --- | --- |
| `cdk: command not found` と表示される | [道具を入れる](<<= guide_link('staff/preparation/environment-start.md#12') =>>) の `npm install -g aws-cdk` を実行する |
| `Token has expired`、`The SSO session associated with this profile has expired` と表示される | 手元で [AWS の認証方式に合わせたログイン](<<= guide_link('staff/environment/procedures/environment.md#sso-login') =>>) を再実行する |
| `is not authorized to perform`、`AccessDenied` と表示される | 表示された操作の権限を管理者に依頼する（一覧は [アクセス制御の仕様](<<= guide_link('staff/environment/specs/access-control.md') =>>)） |
| synth で `availability_zones と max_azs はどちらか一方だけを指定してください` と表示される | 設定ファイルの `max_azs` の行を消す（[Availability Zone を選ぶ](<<= guide_link('staff/preparation/placement.md#26-availability-zone') =>>)） |
| synth で `instance.availability_zone は network.availability_zones のいずれかで指定してください` と表示される | `availability_zone` を `availability_zones` に書いたものの中から選ぶ（[Availability Zone を選ぶ](<<= guide_link('staff/preparation/placement.md#26-availability-zone') =>>)） |
| synth で `instance.availability_zone ... に含まれません` と表示される | [Availability Zone を選ぶ](<<= guide_link('staff/preparation/placement.md#26-availability-zone') =>>) の「Availability Zone を指定する場合」のとおり、`availability_zones` にその Availability Zone を加えて書く |
| `/cdk-bootstrap/hnb659fds/version` が見つからないと表示される | 管理者に CDK のブートストラップを依頼する（[AWS アカウントの状態を確かめる](<<= guide_link('staff/preparation/environment-start.md#13-aws') =>>)） |
| deploy が `InsufficientInstanceCapacity` で失敗する | AWS 側の空き容量が足りない。[GPU の空き容量不足で起動できないとき](<<= guide_link('staff/environment/procedures/environment.md#insufficient-instance-capacity') =>>)で対処する。vCPU クォータ不足とは別 |
| deploy が `VcpuLimitExceeded` で失敗する | vCPU クォータが足りない。管理者にクォータの引き上げを依頼する（[AWS アカウントの状態を確かめる](<<= guide_link('staff/preparation/environment-start.md#13-aws') =>>)） |
| deploy が `OptInRequired`、Marketplace の購読についてのエラーで失敗する | 管理者に AMI の製品の購読を依頼する（[管理者に依頼するもの](<<= guide_link('staff/preparation/environment-start.md#11') =>>)） |
| deploy・destroy が `disableApiTermination` や終了保護についてのエラーで失敗する | 対象の EC2 の終了保護を外してからやり直す（[作り直しの前の準備](<<= guide_link('staff/environment/procedures/environment.md#61-作り直しの前の準備') =>>)または[撤去する](<<= guide_link('staff/environment/procedures/environment.md#7-撤去する') =>>)の終了保護解除） |
| deploy が `already exists` と表示して失敗する（バケット名） | 同じ開催 ID で作ったバケットが残っている。別の開催 ID にするか、中身を確かめてから [撤去する](<<= guide_link('staff/environment/procedures/environment.md#7-撤去する') =>>)の「残った S3 バケットを削除する」 でバケットを削除する |
| 初回の deploy が失敗し、スタックの状態が `ROLLBACK_COMPLETE` になった | [撤去する](<<= guide_link('staff/environment/procedures/environment.md#7-撤去する') =>>)のスタック削除 で一度削除し、原因を直してから [構築する](<<= guide_link('staff/preparation/deploy.md#4') =>>)をやり直す。バケット名のエラーが出たら上の行の対処をする |
| EC2 の起動ディスクの容量が `root_volume_size_gb` にならず、別のディスクが付いている | `root_device_name` が AMI と違う。[ルートデバイス名を調べる](<<= guide_link('staff/preparation/placement.md#25') =>>) で調べ直し、[作り直しの前の準備](<<= guide_link('staff/environment/procedures/environment.md#61-作り直しの前の準備') =>>) の準備をしてから deploy し直す |
| [（任意）ソフトウェアを導入済みの AMI を用意する](<<= guide_link('staff/preparation/ami-find.md#24-ami') =>>) で一時的なインスタンスの `PingStatus` が `Online` にならない、`start-session` で接続できない | 数分待つ。続く場合は、インスタンスプロファイルに `AmazonSSMManagedInstanceCore` が付いているか、subnet からインターネットに出られるか（パブリック IP が付いているか）を管理者と確かめる |
| deploy が `smaller than snapshot` と表示して失敗する | [（任意）ソフトウェアを導入済みの AMI を用意する](<<= guide_link('staff/preparation/ami-find.md#24-ami') =>>) の導入済みの AMI のスナップショットが `root_volume_size_gb` より大きい。`root_volume_size_gb` を [作ってある導入済みの AMI を探す](<<= guide_link('staff/preparation/ami-find.md#241-ami') =>>) の 2 で表示される大きさ以上にする |
| [（任意）インスタンスの中身を確かめる](<<= guide_link('staff/preparation/verify.md#54') =>>) の `start-session` で接続できない | 起動直後は数分待つ。続く場合は、AMI に SSM Agent（EC2 側で接続・操作を受け付けるソフトウェア）が入っているかを確かめる |
| 講師の払出しが `SSM パラメータ ... から読めませんでした` で失敗する | 講師の権限に [講師に払出し用のアクセスキーを読む権限を与える](<<= guide_link('staff/preparation/verify.md#52') =>>) のポリシーがあるか、講師のプロファイルと設定ファイルの開催 ID・リージョンが正しいかを確かめる |
| 受講者の認証情報が 1 時間で切れる | 講師が講師用のコマンドを使わずに作っている。[講師の手順](<<= guide_link('staff/environment/handoff.md') =>>) のコマンドで払い出し直してもらう（[払出し用の鍵ができたことを確かめる](<<= guide_link('staff/preparation/verify.md#51') =>>) の注意） |
| 受講者を増やしたのに、その受講者の認証情報を作れない | [受講者を増やす](<<= guide_link('staff/environment/procedures/environment.md#62') =>>) の deploy が済んでいるかを確かめる |


### GPU の空き容量不足で起動できないとき {#insufficient-instance-capacity}

`InsufficientInstanceCapacity` は、選んだ区画・インスタンスタイプに対して AWS が今用意できる空き容量が足りないことを示します。提供対象の Availability Zone でも、他の利用者の使用などで起こります。

- 数分待ってから再試行します。
- 続く場合は、[Availability Zone を選ぶ](<<= guide_link('staff/preparation/placement.md#26-availability-zone') =>>)で、そのインスタンスタイプを提供する別の区画を選び、設定ファイルを変更して構築を再試行します。
- 開催中の環境を変更する場合は、先に[作り直しの前の準備](<<= guide_link('staff/environment/procedures/environment.md#61-作り直しの前の準備') =>>)を行います。

`VcpuLimitExceeded` はアカウントの vCPU クォータ不足なので、[AWS アカウントの状態を確かめる](<<= guide_link('staff/preparation/environment-start.md#13-aws') =>>)で利用上限と必要数を確認し、管理者に引き上げを依頼します。クォータを引き上げても、AWS 側の空き容量を増やすことにはなりません。[AWS の起動トラブル対処](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/troubleshooting-launch.html)も参照してください。
