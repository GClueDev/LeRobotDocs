## 1. 受講者に成果を保存してもらう

受講者 PC で開催環境の `activate` を読み込みます。保存対象を例の `./checkpoints` に集め、次を実行します。例のディレクトリ名・保存先は各自の実際のものへ置き換えます。

```bash
gclue-ai-handson-attendee files upload ./checkpoints --to models/final
gclue-ai-handson-attendee files pull --own --prefix models/final \
  --dest ./recovered-final
diff -qr ./checkpoints ./recovered-final/checkpoints
```

ディレクトリをアップロードすると元のディレクトリ名 `checkpoints` が付くため、取得先にもその階層があります。転送は同期ではなく、古いファイルの削除は行いません。新しい保存先を使い、元データと取得先の比較が終了コード 0 になることを確認します。大きな成果はファイル一覧・サイズ・内容も確認します。EC2 にだけある成果は、本人が EC2 の受講者ツールを有効化し、`files upload` で本人の S3 バケットパスへ保存してから PC に回収します。

EC2 にだけ `./checkpoints` がある場合は、EC2 の ubuntu ユーザーで、成果があるディレクトリに移動して次を実行します。受講者ツールは講師が EC2 に導入済みであることを確認してください。

```bash
source ~/gclue-ai-handson/{{EVENT_ID}}/activate
gclue-ai-handson-attendee files upload ./checkpoints --to models/final
```

その後 PC で前述の `files pull` を実行し、EC2 の元データと取得データのファイル一覧・サイズと、推論に使う設定ファイル・モデルファイルの存在を確認します。PC に元の `./checkpoints` がなければ、PC 同士の `diff` だけで EC2 データの一致を判定しないでください。

進捗表には受講者 ID、回収先、比較結果、確認時刻だけを記録します。未回収者がいる間は失効・削除へ進みません。認証が切れていたら [認証の更新](<<= guide_link('staff/instructor/support.md') =>>) を行います。
