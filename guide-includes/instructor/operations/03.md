## 用意するもの

| もの | 入手先 | 説明 |
| --- | --- | --- |
| このリポジトリ | Git | リポジトリ直下で `uv sync` を済ませておく |
| 開催の設定ファイルのディレクトリ | 構築担当 | `{{CONFIG_DIR}}/`（中に `gclue-ai-handson-config.yml`）。設定ファイルは Git で共有されるので、[最新の設定ファイルを取得する](<<= guide_link('staff/instructor/operations.md#11') =>>)で `git pull` して取得する |
| 講師用の AWS のユーザー | AWS アカウントの管理者 | 講師の権限を管理者が付与した、IAM Identity Center のユーザー、または IAM ユーザー |
| 名前付き AWS CLI プロファイル | 各自 | 上のユーザーで、自分の作業環境に自分で作る。名前は自分で決める（作り方は [講師用のアカウントでログインする](<<= guide_link('staff/instructor/operations.md#12') =>>)） |
| AWS CLI v2 | 各自 | ログインに使う |
| Session Manager プラグイン（SSM 経由のシェル接続・ポート転送用） | 各自 | 受講者の EC2 へ認証情報を直接書き込むとき（[受講者の EC2 へ直接書き込む](<<= guide_link('staff/instructor/operations.md#31-ec2') =>>)）に使う |
| 講義資料のディレクトリ | 講師 | 受講者の EC2 の `/opt/handson/` に置きたい講義資料・ツール |

以降の運用コマンドは、すべて構築担当から案内された **ai-learning-handson-aws-infra の作業環境（dev container）内のリポジトリ直下**で実行します。LeRobotDocs の作業ディレクトリでは実行しません。受講者に伝えるコマンドは受講者の PC または明記した EC2 上で実行します。
構築担当から受け取った開催設定の場所と、講師自身の AWS プロファイルを下の欄へ入力します。例: `config/environments/workshop01` と `GClue-Instructor`。

<div data-aws-values-panel data-aws-inline data-aws-fields="CONFIG_DIR PROFILE EVENT_ID ATTENDEE_ID MATERIALS_DIR"></div>

主要な引数の一覧は次で確認できます。

```bash
uv run gclue-ai-handson release --help
uv run gclue-ai-handson credentials --help
uv run gclue-ai-handson rollout --help
```
