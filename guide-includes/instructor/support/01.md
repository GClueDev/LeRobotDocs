## 導入と認証の更新

初回は講師が個別配布した `.env` を保存します。通常はこの1ファイルで導入できます。講師が `aws-profile` 形式で発行した場合だけ、同名の `.credentials` も同じディレクトリに保存します。認証ファイル・期限付き URL は共通フォームに入力せず、次のコードを手元で手動置換します。講師から届いた期限付き導入 URL を `<導入 URL>`、`.env` のパスを `<認証情報ファイル>` に置き換えます。

```bash
curl -fsSL '<導入 URL>' -o bootstrap.sh
bash bootstrap.sh --env-file '<認証情報ファイル>'
source ~/gclue-ai-handson/{{EVENT_ID}}/activate
gclue-ai-handson-attendee env info
```

開催 ID、本人の ID、教材の版、有効期限が合えば次へ進みます。既に導入済みで期限が切れた場合は、講師が再発行したファイルを同じ場所にそろえてから更新します。

```bash
gclue-ai-handson-attendee env credentials \
  --env-file '<新しい認証情報ファイル>'
source ~/gclue-ai-handson/{{EVENT_ID}}/activate
gclue-ai-handson-attendee env info
```

開いているターミナルごとに読み込み直します。EC2 の認証情報は PC とは別です。講師の `credentials send --ec2` 後は、対象 EC2 の Linux ユーザー `ubuntu` で[導入先に保存された認証情報を更新する](<<= guide_link('staff/preparation/rollout.md#ec2-credentials') =>>)手順を実行します。送信先の `/tmp` ファイルを読み込むだけでは、導入済みツールの認証情報は更新されません。再起動で `/tmp` が消えた場合は再送が必要です。
