## 4. 受講者の EC2 へ一斉に配る

一斉配布は、受講者の EC2 の `/opt/handson/` を指定した版の内容にそろえます。
受講者の作業場所（`/home/ubuntu/` の中。`~/handson` は `/opt/handson/` へのリンク）は変更しません。
受講者が `/opt/handson/` の中のファイルを書き換えていた場合、そのファイルは上書きせず「衝突」として報告します。
一斉配布では現行版は使わず、毎回 `--version` で版を指定します（[教材の版と一斉配布の仕様](<<= guide_link('staff/instructor/contracts.md') =>>)）。

`--manifest-sha256` には、[版を作る](<<= guide_link('staff/preparation/materials.md#21') =>>) で控えた SHA-256 を指定します。
省略もできますが、指定すると、意図した中身の版であることを配る前に確かめられます。

公開した教材の版と、教材の版を作ったときに控えた manifest の SHA-256（64桁の16進数）を確認します。受講者 ID は対象を1名に絞る場合に本人の ID を使います。

<div data-aws-values-panel data-aws-inline data-aws-fields="RELEASE MANIFEST_SHA ATTENDEE_ID"></div>

### 4.1 初回の一斉配布

受講者がまだ EC2 で作業していない段階（講習会の前）に、1 回だけ行います。
受講者の EC2 がすべて起動していることを確かめてから実行します。

```bash
uv run gclue-ai-handson rollout provision \
  --env-dir {{CONFIG_DIR_SH}} --version {{RELEASE}} \
  --manifest-sha256 {{MANIFEST_SHA}}
```

確認を求められたら、表示された台数と版を確かめて `y` を入力します。標準入力のない実行では確認待ちになるため、対象を事前確認した自動化に限り `--yes` を指定できます。
`初回構築: 成功 <台数> 台、失敗 0 台、衝突 0 件` と表示されれば成功です。

- `対象外: {{ATTENDEE_ID}} ...` と表示された EC2 には配られていません。起動してから、`--attendee {{ATTENDEE_ID}}` を付けて同じコマンドを実行します。
- 初回の一斉配布の後、受講者は Amazon DCV（リモートデスクトップ接続）のログイン用パスワードを自分で設定します（[受講者の手順](<<= guide_link('staff/instructor/support.md') =>>)）。

### 4.2 講義中に訂正を配り直す

講義中に教材を訂正するときは、次の順に進めます。
EC2 の中身を元に戻す（差し戻す）ときも、戻したい版を `{{RELEASE}}` に指定して同じ手順で配ります。

1. 訂正した教材で新しい版を作り、公開する（[版を作る](<<= guide_link('staff/preparation/materials.md#21') =>>)、[版を公開する](<<= guide_link('staff/preparation/materials.md#22') =>>)）。

   手元の機器の現行版はまだ切り替えない場合は、公開に `--no-latest` を付けます。
2. 受講者に、適用する時刻と、作業中のファイルを保存してほしいこと、`~/handson`（`/opt/handson/`）の中のファイルは編集しないでほしいことを伝える。
3. 変更の予定と衝突を確かめる（何も変更しません）。

   ```bash
   uv run gclue-ai-handson rollout check --env-dir {{CONFIG_DIR_SH}} \
     --version {{RELEASE}} --manifest-sha256 {{MANIFEST_SHA}}
   ```

   確認: 最後に `差分確認: 成功 <台数> 台、失敗 0 台、衝突 <件数> 件` と表示されます。
   `衝突: <パス>` と表示されたファイルは、その受講者が書き換えたため上書きされません。
   上書きしてよいか受講者と相談し、必要なら受講者に自分の作業場所へ移してもらいます。
4. 適用する。

   ```bash
   uv run gclue-ai-handson rollout patch --env-dir {{CONFIG_DIR_SH}} \
     --version {{RELEASE}} --manifest-sha256 {{MANIFEST_SHA}}
   ```

   全台の事前確認、全台のバックアップ（ディスクのスナップショット）の作成、試験の 1 台への適用、残りへの少しずつの適用の順に自動で進みます。
   事前確認の後に確認を求められたら、表示された台数と衝突の件数を確かめて `y` を入力します。
   表示される `パッチ ID: <ID>` は、片付けや調査に使うので控えておきます。

   確認: 最後に `パッチ: 成功 <台数> 台、失敗 0 台、衝突 <件数> 件（試験の 1 台を除く）` と表示されれば成功です。
   事前確認や試験の 1 台で失敗すると、残りには適用せずに止まります。
5. `対象外` や `失敗` と表示された受講者がいれば、原因を取り除いてから `--attendee {{ATTENDEE_ID}}` を付けて、変更予定と衝突の確認（`rollout check`）、訂正の適用（`rollout patch`）を繰り返す。
6. 受講者に、適用が終わったことを伝える。

   手元の機器でも新しい版を使う場合は、受講者の PC のターミナルで次を実行してもらいます。`--no-latest` で公開した場合は、先に[現行版を切り替える・前の版に戻す](<<= guide_link('staff/preparation/materials.md#23') =>>) で現行版を切り替えます。

   ```bash
   source ~/gclue-ai-handson/{{EVENT_ID}}/activate
   gclue-ai-handson-attendee env update
   gclue-ai-handson-attendee env info
   ```

   導入済み環境の設定を確認する `env info` に表示された教材の版が、講師の案内した版と一致することを確認します。

教材の訂正適用コマンド `rollout patch` が出した「パッチ ID:」の値を下の欄へ控えます。後でバックアップの対象を調べるための ID です。パッチを適用していなければ入力しません。

<div data-aws-values-panel data-aws-inline data-aws-fields="PATCH_ID"></div>

上書きされたファイルの元の内容は、受講者の EC2 の `/var/backups/handson/{{PATCH_ID}}/` に残っています。


### 4.3 EC2 に受講者ツールを用意する {#ec2-attendee-tools}

受講者の PC と EC2 で同じ `files upload/pull` を使うため、教材配布の後、受講者が作業を始める前に実施します。ツールの公開（[受講者用ツールを公開する](<<= guide_link('staff/preparation/instructor-start.md#13') =>>)）と全 EC2 の起動を済ませてください。開催・受講者ごとのバケットパスは認証情報ファイルに設定済みです。

講師の運用環境で、EC2 に受講者自身の一時認証情報を書き込みます。

```bash
uv run gclue-ai-handson credentials send --env-dir {{CONFIG_DIR_SH}} \
  --ec2 --duration-seconds 28800
```

以下は対象の EC2 の **ubuntu ユーザーの Terminal** で、講師が受講者ごとに実行します。右上の設定を対象者の開催・受講者 ID に合わせ、`whoami` が `ubuntu` であることを確認してください。講師の AWS 認証情報を EC2 に渡しません。

```bash
whoami
ENV_FILE=/tmp/gclue-ai-handson-{{EVENT_ID}}-{{ATTENDEE_ID}}.env
source "$ENV_FILE"
BOOTSTRAP_DIR=$(mktemp -d)
BOOTSTRAP_URI="s3://$GCLUE_AI_HANDSON_BUCKET"
BOOTSTRAP_URI+="/shared/tools/attendee/bootstrap.sh"
aws s3 cp "$BOOTSTRAP_URI" "$BOOTSTRAP_DIR/bootstrap.sh"
bash "$BOOTSTRAP_DIR/bootstrap.sh" --env-file "$ENV_FILE" \
  --no-materials --no-hook
source ~/gclue-ai-handson/{{EVENT_ID}}/activate
gclue-ai-handson-attendee env info
```

導入先は `~/gclue-ai-handson/{{EVENT_ID}}/` です。教材は一斉配布済みなので再取得せず、教材のセットアップ処理も実行しません。`env info` の開催 ID が開催設定の `{{EVENT_ID}}`、受講者 ID が対象者の `{{ATTENDEE_ID}}` と一致し、有効期限が現在より後であることを確認します。受講者用ツールの manifest SHA-256 は、公開時に控えた `{{TOOLS_MANIFEST_SHA}}` と一致させます。これは教材の版のハッシュ `{{MANIFEST_SHA}}` とは別です。全員の導入が済んでから受講者の操作へ進みます。

### EC2 の導入先の認証情報を更新する {#ec2-credentials}

認証情報を再発行したときは、EC2 への `credentials send` の後、対象 EC2 の ubuntu ユーザーで導入先の認証情報も入れ替えます。元の `/tmp` ファイルへの書き込みだけでは、導入先へコピーした認証情報は更新されません。

```bash
source ~/gclue-ai-handson/{{EVENT_ID}}/activate
ENV_FILE=/tmp/gclue-ai-handson-{{EVENT_ID}}-{{ATTENDEE_ID}}.env
gclue-ai-handson-attendee env credentials --env-file "$ENV_FILE"
source ~/gclue-ai-handson/{{EVENT_ID}}/activate
gclue-ai-handson-attendee env info
```

受講者には、EC2 でも新しい Terminal を開いたら `activate` を読み込むことと、認証が期限切れなら講師に更新を依頼することを伝えてください。ツール導入は受講者の主手順に追加しません。
