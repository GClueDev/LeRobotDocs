## 5. 構築後に行うこと

### 5.1 払出し用の鍵ができたことを確かめる

講師が受講者に、講習会の AWS 環境を操作するための一時 AWS 認証情報を発行するときは、構築で作られた「払出し専用ユーザー」（人ではなく、発行処理に使う IAM ユーザー）のアクセスキーを使います。受講者には有効期限のある一時認証情報を渡します。払出し専用ユーザーの恒久的なアクセスキーは発行処理用で、受講者へ渡すものではありません。
その鍵は、AWS Systems Manager（SSM）の Parameter Store（認証情報の保管先）のパラメータ `/GClueAiHandsOn/{{EVENT_ID}}/IssuerAccessKey` に暗号化して保存されています。
パラメータが 1 件表示されれば成功です（鍵の値は表示されません）。

```bash
aws --profile {{PROFILE_SH}} --region {{REGION}} \
  ssm describe-parameters --parameter-filters \
  Key=Name,Values=/GClueAiHandsOn/{{EVENT_ID}}/IssuerAccessKey \
  --query 'Parameters[].[Name,Type]' --output text
```

`SecureString` と表示されることも確かめます。

!!! warning "受講者の認証情報は払出し専用ユーザーで作ります"
    **ロールの一時認証情報を使って別のロールを引き受ける場合**は「ロールの連鎖」になり、発行できるセッションは最長 1 時間です。IAM Identity Center、外部 IdP、IAM ユーザーのいずれでログインした場合も、既にロールを引き受けていれば、この制約に当たります。

    IAM ユーザーの恒久的なアクセスキーから直接ロールを引き受ける場合はロールの連鎖ではなく、この 1 時間の制限は適用されません。[AWS の AssumeRole の仕様](https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html)も参照してください。

    この環境では、講師の認証方式にかかわらず、運用ツールが払出し専用 IAM ユーザーのアクセスキーを読み出して発行します。信頼ポリシーは払出し専用ユーザーだけを許可しているため、講師自身の IAM ユーザーのキーやロールで直接代用できません。信頼ポリシーを変更せず、講習会用コマンドで発行してください。

### 5.2 講師に払出し用のアクセスキーを読む権限を与える {#52}

講師が払出しの操作をするには、講師の権限に次の 2 つだけが必要です。
`AdministratorAccess` を持つ講師には、追加の作業は要りません。

- パラメータ `/GClueAiHandsOn/{{EVENT_ID}}/IssuerAccessKey` の `ssm:GetParameter`
- AWS 管理キー `aws/ssm` での `kms:Decrypt`

> **注意**
>
> このパラメータを読める人は、受講者の認証情報を作ることと、講師用の操作（教材の配布など）ができます。
> 必要な講師だけに与え、他の人には与えないでください。

キーの ARN を表示します。

```bash
aws --profile {{PROFILE_SH}} --region {{REGION}} \
  kms describe-key --key-id alias/aws/ssm --query KeyMetadata.Arn \
  --output text
```

講師の権限（IAM Identity Center の権限セットのインラインポリシーなど）に、次のポリシーを加えます。
リージョン・アカウント ID・開催 ID と、直前の `KeyMetadata.Arn` の出力を確認します。KMS キー ARN は下の欄へ転記します。これはキーの識別子で、鍵の秘密値は入力しません。

<div data-aws-values-panel data-aws-inline data-aws-fields="ISSUER_KMS_ARN"></div>


```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "ssm:GetParameter",
      "Resource": "arn:aws:ssm:{{REGION}}:{{ACCOUNT_ID}}:parameter/GClueAiHandsOn/{{EVENT_ID}}/IssuerAccessKey"
    },
    {
      "Effect": "Allow",
      "Action": "kms:Decrypt",
      "Resource": {{ISSUER_KMS_ARN_YAML}}
    }
  ]
}
```

講師が [講師の手順](<<= guide_link('staff/environment/handoff.md') =>>) の認証情報の払出しを実行し、エラーにならなければ成功です。

### 5.3 講師に設定ファイルを渡す

講師も同じ設定ファイルを使います。
`{{CONFIG_DIR}}/gclue-ai-handson-config.yml` を講師に渡し、講師が `git clone` した `ai-learning-handson-aws-infra` の同じ場所に置いてもらってください。
講師は、`aws.profile` を、自分の作業環境に作ったプロファイルの名前に書き換えます。

設定ファイルの受講者一覧（`aws.handson.attendees`）にある受講者 ID を、下の欄に入力します。講師が最初に操作する受講者の ID にします（例: 一覧の先頭の `attendee01`）。

<div data-aws-values-panel data-aws-inline data-aws-fields="ATTENDEE_ID"></div>

あわせて、右上の「各種値の設定」の「エクスポート」で設定JSONを保存し、講師に渡します。講師はこれを読み込み、開催設定ディレクトリ・開催 ID・受講者 ID・リージョン・S3 バケット名が入っていることを確かめます。

設定ファイルにはアカウント ID が入るため、Git にコミットしたり、公開の場所に置いたりしないでください。
以降の作業（受講者用ツールの公開、教材の配布、認証情報の払出し）は [講師の手順](<<= guide_link('staff/environment/handoff.md') =>>) で行います。

### 5.4 （任意）インスタンスの中身を確かめる

AMI の条件（[AMI を選ぶ](<<= guide_link('staff/preparation/event-settings.md#23-ami') =>>)）を満たしているかは、インスタンスの中で確かめます。
Session Manager プラグイン（SSM 経由のシェル接続・ポート転送用）が入っている PC で、受講者のインスタンスの 1 台に入ります。
`{{INSTANCE_ID}}` は [構築する](<<= guide_link('staff/preparation/deploy.md#4') =>>)で表示した `i-` で始まる値です。

```bash
aws --profile {{PROFILE_SH}} --region {{REGION}} \
  ssm start-session --target {{INSTANCE_ID}}
```

入れれば、EC2 側で接続・操作を受け付ける SSM Agent は動いています。
まず、AMI の対象（OS、アーキテクチャ、NVIDIA ドライバーと GPU）を確かめます。中で次を実行します。

```bash
cat /etc/os-release
uname -m
nvidia-smi
```

OS が Ubuntu 24.04、アーキテクチャが `x86_64` であり、`nvidia-smi` がエラーなくドライバーと GPU の情報を表示すれば成功です。

受講者が SSH・git で接続する講習会では、続けて中で次を実行します。

```bash
sudo -n -u ubuntu true && echo sudo-ok
ss -ltn 'sport = :22' | grep -q LISTEN && echo sshd-ok
test -f /etc/ssh/ssh_host_ed25519_key.pub && echo hostkey-ok
command -v git flock
```

`sudo-ok`、`sshd-ok`、`hostkey-ok` と、`git` と `flock` の場所の 2 行が表示されれば、SSH・git で接続できます。
`sudo-ok` が表示されない場合は、Session Manager で入ったユーザーから `ubuntu` ユーザーへパスワードなしで切り替えられません。
別の AMI を選ぶか、AMI の sudo の設定を確かめてください。

`exit` で接続を終了します。
