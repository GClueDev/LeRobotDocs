# 各種値の設定の使い方

全ページ右上の「各種値の設定」、または手順内の関連する入力欄を使い、この開催で使う値を一度入力すると、本文とコマンドへ反映されます。このページは入力の意味と受け渡し方法の説明です。実値の初期設定はありません。

{% if audience == "staff" %}
講習会側版では、受講者・講師・環境構築担当者の項目を同じフォームで設定できます。講習会側版専用の保存領域を使い、他の版で保存した値は共通JSONで受け渡します。
{% endif %}

このガイドでは、S3バケット内の保存場所を「S3 バケットパス」と呼びます。コマンドの `--prefix` には、各手順で示す相対パスを指定します。

## 入力する値の意味と例

下の例は説明用の架空の値です。**例をそのまま入力せず、講師から受け取った設定JSONまたは案内を優先してください。** 未確定の項目は空欄のまま講師に確認します。

| フォームの項目（コマンドでの名前） | 何のための値か・使う場所 | 説明用の例 | 誰が決めるか |
| --- | --- | --- | --- |
| 開催 ID（`EVENT_ID`） | どの講習会かを区別する名前。手元のツールの配置先にも使う | `workshop01` | 講師が配布。自分で別名を付けない |
| 受講者 ID（`ATTENDEE_ID`） | 自分専用のEC2とS3の保存領域を区別する名前。氏名やメールアドレスとは別 | `attendee01` | 講師が自分用に配布。他の人のIDを使わない |
| S3 バケット名（`BUCKET`） | AWS上でファイルを保管する入れ物の名前。`s3://`や末尾のパスは入力しない | `example-handson-workshop01` | 講師が配布。受講者はバケットを作らない |
| AWS リージョン（`REGION`） | AWSのどの地域の設備を使うかを表す名前 | `ap-northeast-1`（東京） | 講師が配布。自分の住所から選ばない |
| EC2 のデータセットディレクトリ（`DATASET_DIR`） | AWS上の自分用PCで、映像と動作記録を置くフォルダの絶対パス。手元のPCの場所ではない | `/home/ubuntu/handson-data/workshop01/attendee01/round1` | 配布データは講師の配置先。自分の収集データは[収集後の転送](lerobot/collect.md#transfer-to-ec2)で講師と未使用の取得先を確認する |
| データセット識別名（`DATASET_REPO_ID`） | LeRobotが一組の映像と動作記録を識別する名前。フォルダやS3バケットの名前とは別 | `attendee01/red-cube`（所有者名/データ名の形式） | 講師指定。手元で収集するときとEC2で使うときは同じ名前を入力する |

手元のロボットを使うコースでは、接続確認で次の3項目も入力します。機器に合わせて本人と講師が確認する値なので、講師の共通JSONに入っていなければ空欄のまま受け取り、検出後に入力します。

| 設定欄（コマンドでの名前） | 使う場所・決め方 | 説明用の例 |
| --- | --- | --- |
| 手元の LeRobot 作業フォルダ（`PROJECT_DIR`） | 手元に準備したLeRobotの配置先を講師に確認する | Mac `/Users/student/lerobot`、Jetson `/home/student/lerobot` |
| Leader の USB 接続先（`TELEOP_PORT`） | 手元で検出した、人が動かすアームの接続先 | Jetson `/dev/ttyACM0`、Mac `/dev/tty.usbmodem12301` |
| Follower の USB 接続先（`ROBOT_PORT`） | 手元で検出した、追従するアームの接続先 | Jetson `/dev/ttyACM1`、Mac `/dev/tty.usbmodem12302` |

実習中の入力欄も右上の設定と同じ値を使います。

| 項目 | 入力するページ・用途 |
| --- | --- |
| 手元の保存先・課題文 | 接続確認で決め、収集・推論に引き継ぐ |
| front / side の接続先 | カメラの調整で検出結果を入力する |
| 学習実行名・EC2 の結果保存先 | 学習で未使用の名前・絶対パスを入力し、同じ値でモデルを回収する |
| 手元の推論モデルの場所 | 学習後の回収で表示された場所を入力し、推論で使う |

絶対パスは、`/`から始まるフォルダの場所を全部書いたものです。EC2の例はEC2でのみ使います。手元のMacのホームフォルダは、例えば`/Users/student`です。`student`は説明用のユーザー名で、実際のホームフォルダは手元のターミナルで次を実行して確認できます。

```bash
echo "$HOME"
```

「各種値の設定」は、このWebページに載せる値を保存するフォームです。**入力しただけでは、PC上にフォルダを作ったり、ターミナルの設定を変更したりしません。** 各手順で値が埋まったコマンドをコピーし、指定された機器のターミナルで実行します。

全ページのヘッダーにある「各種値の設定」ボタンで、入力フォームをモーダルで開きます。ページを移動せず編集でき、ページを移動しても同じ保存値を使います。閉じるボタンまたは Escape で戻ります。閉じても入力した有効な値は保存されます。

実習中に決まる USB 接続先・カメラ接続先・収集先・課題文・学習実行名・結果の保存先・推論モデルの場所は、各手順の近くにも入力欄があります。どちらで編集しても同じ役割の保存値とコマンドへ即時反映されます。PC と EC2 のブラウザが別の場合は設定JSONで受け渡すか、必要な値を同じ内容で入力してください。

## 入力と保存の使い方

- 入力した有効な値は、このブラウザのこの役割用に保存されます。ページを移動しても引き継がれ、「リセット」を押して削除を確認すると空欄へ戻ります。
- 受講者・講師・環境構築担当者はそれぞれ独立した保存領域です。既存の LeRobot の値設定にも影響しません。ホスト名やポートが違うURLではブラウザの保存領域も異なります。
- パスは引用符を付けず入力します。空白やアポストロフィはそのままで構いません。`~` は使わずホームディレクトリの絶対パスにしてください。コマンド引数の引用符は自動で付きます。
- 認証情報の本文、アクセスキー、パスワード、期限付きURLは入力しないでください。そのための保存欄はありません。認証ファイル名・期限付きURLなどの手動指定項目は各手順で置き換えます。
- 未設定・形式不正・手動指定の項目が残る場合も、「コピー」で現在表示中の内容をコピーできます。未設定表示や山括弧の項目はエディタで置き換えてから実行してください。注意書き自体はコピーに含みません。
- 入力は端末の環境変数を設定しません。`$AWS_PROFILE` 等のシェル変数は書き換えず、実行場所やログイン条件は各手順に従います。

## 反映されるコマンド

以下は値の反映を確認するための表示です。実行する場合は手順ページの前提と実行場所を確認してください。

```bash
source ~/gclue-ai-handson/{{EVENT_ID}}/activate
gclue-ai-handson-attendee env info
```

EC2 のデータセット確認では、値を別途ターミナル変数に設定せず、次のようにコマンドの引数へ直接入れます:

```bash
uv run --no-sync lerobot-edit-dataset \
  --root {{DATASET_DIR_SH}} \
  --repo_id {{DATASET_REPO_ID_SH}} \
  --operation.type info
```

## 設定ファイルの受け渡し

「エクスポート」でバージョン付きの共通JSONを保存し、別の役割の「インポート」で読み込みます。右上の設定モーダルで使えます。許可された有効な項目だけを採用し、読み込んだ値を同名の設定へ反映します。ファイルにない項目・不正な項目は既存値を維持します。採用・無視した項目名は結果に表示されます。

この役割のフォームにない、他の役割用の有効な項目も保存して再エクスポートできます。知らない項目名や不正値は保存しません。認証情報を渡す形式ではありません。「リセット」は、他の役割用に保持した値も含め、この役割の保存領域を空にします。確認で「はい、削除する」を選んだときだけ消えます。

## 講師から受け取った設定JSONを使う

`受講者ID.guide-settings.json` を受け取った場合は、「インポート」で読み込みます。開催ID・自分の受講者ID・S3バケット・リージョンなど、講師側で確定した項目が埋まります。データセットの値が確定している場合は、その値も含まれます。残った未入力項目は手順に従って補ってください。

このJSONは一時認証情報の代わりではありません。認証情報の `.env`・`.credentials` は導入手順で使用し、このフォームには読み込みません。インポート時はJSONにある項目だけを更新し、含まれていない既存値は維持します。別の開催や受講者に切り替える場合は、必要に応じて「リセット」で入力と保存した値を消してから読み込みます。

## 受講者へ渡す設定JSONを作る

確定した受講者向け項目を入力し、「受講者向けをエクスポート」を押します。出力するのは開催ID・受講者ID・S3バケット・リージョン・データセットディレクトリ・データセット識別名・手元のLeRobot作業フォルダ・Leader/FollowerのUSB接続先のうち入力済みの有効な値だけです。講師のプロファイル・設定ディレクトリ・アカウントIDなどは含めません。受講者IDが未入力なら全員共通の設定JSONとして作成できます。

## 講習会側の準備で入力する値

講師・構築担当の準備ページにも、関連箇所の入力欄があります。管理者・開催 YAML で決める値（プロファイル、リージョン、開催 ID、配置先など）と、コマンド出力を転記する値（アカウント ID、一時 EC2 ID、新しい AMI ID、manifest SHA-256、パッチ ID、KMS キー ARN）を分けて説明しています。

元の AMI、作成直後の AMI、開催で使う AMI は別の欄です。AMI 作成用の一時 EC2 ID と受講者の EC2 ID、AWS CLI のログインプロファイルと IAM インスタンスプロファイルも別の欄です。選択した ID がどの工程のものか確認してからコピーしてください。

フォームはブラウザの表示値だけを更新します。開催 YAML は自動編集されず、AWS にも何も実行しません。設定値を変更したら、YAML も同じ内容にして検査します。空欄・不正値はコマンドに未設定表示が残り、そのままコピーはできますが実行前に設定が必要です。

教材の版を変更すると、以前の manifest ハッシュはクリアされます。同じ版を作り直した場合も build の最新出力でハッシュを更新してください。設定JSONの版とハッシュは実際の build 出力と照合します。アクセスキー・パスワード・秘密鍵・期限付きURLは入力欄やJSONに含めません。KMS キー ARN はキーの識別子であり、鍵の秘密値ではありません。
